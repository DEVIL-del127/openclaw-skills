# 项目开发日志模板

每个项目交付时写一份开发日志（`开发日志.md`）放项目根目录，随代码入库。
**二次开发前必读**——避免重踩同样的坑。

## 模板结构

```markdown
# <项目名> 开发日志

> 技术栈 / 仓库地址 / 用途
> 说明：**第二次开发前必读**——架构、踩坑、构建流程全记录

## 一、项目定位
一句话说明做什么，核心设计原则。

## 二、代码架构
文件结构 + 模块职责表（| 模块 | 函数 | 说明 |）

## 三、功能清单
按版本列出已完成功能（✅ 开头）。

## 四、踩坑记录（重点！）
每条：现象 → 根因 → 解决 → 教训。⚠️ 标注最高频坑。

## 五、构建/部署流程
可复制的命令序列（打包 → 安装包 → 部署 → 自检）。

## 六、已完成的重要操作
如数据迁移、环境配置（注明"勿重复做"）。

## 七、遗留 / 二次开发 TODO
- [ ] 未完成项、优化项、安全提醒
```

## 写作要点

- 踩坑记录是核心价值——宁可多写，不可漏
- 命令必须可复制可执行
- 敏感信息（token/密码/个人路径）一律不写
- 每个坑标注严重度（⚠️ 高频 / 一般）
- TODO 用 checkbox 便于跟踪

## 与手册的分工

- **开发日志**（项目内）：本项目专属细节
- **通用 skill**（跨项目）：可复用模式（打包/UI/网络），新项目直接参考
